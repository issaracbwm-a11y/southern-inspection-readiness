# ระบบสำรวจความพร้อมการบูรณาการตรวจสอบเครื่องชั่งตวงวัดสินค้าเกษตร ภาคใต้ ปีงบประมาณ 2570

**Southern Inspection Readiness** — เว็บแอปให้ศูนย์/สาขาชั่งตวงวัด 4 หน่วยงานแจ้งความพร้อมด้านเจ้าหน้าที่ รถเครน และรถกระบะ ตามแผนตรวจ 4 รอบ และแสดงผลเป็นแดชบอร์ดสี เขียว / เหลือง / แดง / เทา

## ความสามารถ

- **แดชบอร์ด** การ์ดสรุป 4 รอบ (แผน / ยืนยันพร้อม / ขาด / ร้อยละ) + Readiness Matrix 4 หน่วยงาน × 4 รอบ คลิกดูรายละเอียดรายวัน + กราฟร้อยละความพร้อม
- **แบบสำรวจความพร้อม** แสดงตัวเลขตามแผนของหน่วยงานตนเองอัตโนมัติ กรอกแยกรายวัน บันทึกร่าง / ส่งยืนยัน / แก้ไข / ดูประวัติ
- **รายละเอียดรายวัน** 20 วัน × หน่วยงาน กรองตามรอบ วัน จังหวัด หน่วยงาน สถานะ และดูยอดรวมรายวัน
- **Meeting Mode** สำหรับจอใหญ่ (เต็มจอได้) แสดงตารางความพร้อม ทรัพยากรที่ขาด หน่วยงานที่ยังไม่ตอบ ปัญหาที่ต้องตัดสินใจ และบันทึกข้อสรุปที่ประชุม (แยกจากข้อมูลหน่วยงาน)
- **รายงาน** 6 รายงาน ส่งออก Excel (.xlsx) และพิมพ์/บันทึก PDF ภาษาไทย
- **จัดการแผน** ยืนยันประเด็นที่ข้อมูลต้นฉบับขัดแย้ง (เช่น รถกระบะรอบ 4) และแก้ไขจำนวนตามแผน
- **สิทธิ์ 3 บทบาท** ผู้ดูแลระบบ / เจ้าหน้าที่หน่วยงาน / ผู้บริหาร (ดูอย่างเดียว) บังคับด้วย Supabase Auth + Row Level Security
- **โหมดสาธิต** ทำงานได้ทันทีโดยไม่ต้องมีฐานข้อมูล (มีป้ายแจ้งชัดเจนว่าข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้นเท่านั้น)

## กฎสถานะสี

| สี | สถานะ | เงื่อนไข |
|---|---|---|
| เขียว | พร้อม | ส่งยืนยันแล้ว ครบตามแผนทุกวันทุกรายการ ไม่มีข้อจำกัดสำคัญค้าง และแผนไม่มีข้อขัดแย้ง |
| เหลือง | พร้อมบางส่วน | ส่งยืนยันแล้ว แต่บางรายการ/บางวันไม่ครบ หรือติ๊ก "มีข้อจำกัดสำคัญที่ยังแก้ไม่ได้" |
| แดง | ไม่พร้อม | ยืนยันว่าเข้าร่วมไม่ได้ หรือไม่มีเจ้าหน้าที่พร้อมเลยทุกวัน |
| เทา | ยังไม่ตอบ | ยังไม่ส่งยืนยัน (ฉบับร่างไม่นับ) |
| ม่วง | แผนรอยืนยัน | พร้อมครบ แต่แผนรอบนั้นยังมีข้อขัดแย้งที่กระทบการตัดสินใจ — ระบบจะไม่แสดงสีเขียว |

**การคำนวณนับรายวัน**: แต่ละวันรวมจำนวนที่พร้อมของทุกหน่วยงานที่ส่งยืนยันแล้ว ตัวเลขหลัก "พร้อม/แผน" คือจำนวนที่พร้อมได้ *ทุกวัน* (วันที่น้อยที่สุด) จึงไม่นับรถคันเดิม/คนเดิม 5 วันเป็น 5 ชุด ส่วนร้อยละ = Σ min(พร้อม, แผน) ÷ Σ แผน ของทุกวัน

## เริ่มต้นใช้งานบนเครื่อง

ต้องมี Node.js 22 ขึ้นไป

```bash
npm install
npm run dev          # เปิด http://localhost:5173/southern-inspection-readiness/
npm test             # ทดสอบกฎสถานะ/การคำนวณ 14 กรณี
npm run build        # สร้างไฟล์สำหรับเผยแพร่ในโฟลเดอร์ dist/
```

ถ้าไม่ได้สร้างไฟล์ `.env.local` ระบบจะเปิดใน **โหมดสาธิต** — เลือกผู้ใช้ทดลองได้ทันที และกด "โหลดข้อมูลทดสอบ" เพื่อดูตัวอย่างครบทุกสถานะ

## เผยแพร่บน GitHub Pages

1. สร้าง repository ชื่อ `southern-inspection-readiness` แล้ว push โค้ดขึ้นสาขา `main`
2. Settings → Pages → Source เลือก **GitHub Actions**
3. (เมื่อพร้อมใช้ข้อมูลจริง) Settings → Secrets and variables → Actions เพิ่ม `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY`
4. ทุกครั้งที่ push ขึ้น `main` ระบบจะทดสอบ build และ deploy อัตโนมัติ ที่ `https://<ชื่อบัญชี>.github.io/southern-inspection-readiness/`

> GitHub Pages เผยแพร่เฉพาะหน้าเว็บ (Static) ข้อมูลจริงเก็บใน Supabase เท่านั้น ห้ามใส่ service_role key หรือรหัสผ่านใดๆ ใน repository

## โครงสร้างโปรเจกต์

```
src/
  data/plan.ts            ข้อมูลแผน 4 รอบ (ถอดจากภาพตาราง) + ประเด็นรอยืนยัน
  data/scenarios.ts       ข้อมูลทดสอบตามข้อกำหนดข้อ 13
  lib/readiness.ts        กฎสถานะสีและการคำนวณ (มี unit test)
  lib/repo-demo.ts        ที่เก็บข้อมูลโหมดสาธิต (localStorage)
  lib/repo-supabase.ts    ที่เก็บข้อมูลจริง (Supabase + Realtime)
  lib/reports.ts          รายงาน + ส่งออก Excel
  pages/                  Dashboard, Survey, Daily, Meeting, Reports, Admin, Login
  components/ui/          คอมโพเนนต์สไตล์ shadcn/ui
supabase/migrations/      0001 โครงสร้าง + RLS, 0002 ข้อมูลแผนเริ่มต้น
.github/workflows/deploy.yml
```

เทคโนโลยี: React 18, Vite, TypeScript, Tailwind CSS v4, คอมโพเนนต์แบบ shadcn/ui (Radix), Lucide Icons, Recharts, ExcelJS, Supabase (PostgreSQL + Auth + Realtime), ฟอนต์ Sarabun (ฝังในแอป ไม่ต้องโหลดจากภายนอก)
